# point at which the Metal backend's prefill switches from the GEMV to cpi_gemm_f16 -- so no
# golden in this directory had ever executed that kernel. It was, meanwhile, the most heavily
# benchmarked kernel in the engine.
#

# rows of every tile and every fp16 prompt of >=16 tokens decoded from a corrupted prefill.
# Nothing here failed, because nothing here ran it. The benchmarks did run it, and rewarded it:
# a kernel that skips half its writes is not slower, it is faster.
#

# prefill covers a full tile plus a 22-token remainder -- the padded partial tile is where the
# masking and the bounds checks actually get tested.
